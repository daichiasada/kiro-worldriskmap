# Component bars render empty, plus tab semantics and compare-view gaps

The World Geopolitical Risk Map renders five views (map, ranking, detail, compare, sources) over a static 40-country dataset, with a React-free domain layer (`risk.ts`) computing weighted composite scores, risk bands, and a symmetric bilateral score. The domain math is clean, well-tested, and clamps defensively. The problems are all in the presentation layer: the component-breakdown bars are structurally broken, the tab UI announces roles it doesn't fully implement, and the compare view can put the same country on both sides with a misleading "symmetric" readout.

Watch for: the known bar bug is **confirmed** — `.bar-track`/`.bar-fill` are `<span>`s with no `display` override, so width/height/overflow are ignored and every bar renders as an empty track with no fill (**confirmed**). The ARIA tablist has no `tabpanel` and tabs aren't keyboard-navigable (**confirmed**). The compare view lets A and B be the same country and still labels the result symmetric (**confirmed**).

**Verdict**: NEEDS_CHANGES

## High-level view

The composite-risk domain layer is the strongest part of the change: weights sum to 1.0, every input is clamped to 0–100, bands are classified by monotonic thresholds, and the bilateral score is order-independent, with unit and property tests covering the boundaries that matter.

The component bars are the headline defect. `ComponentBars` builds a track-and-fill structure out of nested `<span>` elements, but the CSS for `.bar-track` and `.bar-fill` sets `height`, `width`, and `overflow` without ever setting `display`. Spans are inline by default, and inline boxes ignore explicit width/height, so the colored fill collapses to nothing and the track renders as a bare 16px-tall strip at best. This affects both the detail view and the compare view, which are the two places the per-component breakdown is shown.

The tab navigation declares `role="tablist"` and `role="tab"` with `aria-selected`, but there is no element with `role="tabpanel"`, no `aria-controls` wiring, and no arrow-key handling — so assistive tech announces a tab widget whose contract isn't met, and keyboard users can only reach tabs via plain tab-order, not the expected arrow keys.

The compare view defaults A and B to distinct countries but places no constraint stopping the user from selecting the same country in both dropdowns; the "対称 (symmetric)" bilateral readout then compares a country to itself, which is a meaningless state the UI presents as valid.

Smaller correctness and robustness gaps: the map tooltip is positioned with `position: fixed` plus `clientX/clientY` offsets but has no viewport-edge clamping, so it overflows near the right/bottom edges; several views index `scored[0]` / `countries[1]` with no guard against a short or empty dataset; and the ranking search mixes case-insensitive Latin matching with case-sensitive raw-substring matching on the Japanese name.

### Component bars collapse to empty tracks

`ComponentBars` renders each row as `<span className="bar-track"><span className="bar-fill" style={{ width, background }} /></span>`. The CSS:

```css
.bar-track { background: var(--panel-2); border-radius: 6px; height: 16px; overflow: hidden; }
.bar-fill  { height: 100%; border-radius: 6px; }
```

Neither rule sets `display`, so both spans are `display: inline`. Inline boxes ignore `width` and `height` and don't establish a block formatting context for `overflow: hidden`. The result: the track's 16px height and the fill's `width: ${value}%` are both dropped, the fill's `height: 100%` resolves against an inline box with no defined height, and the user sees no bar. The `.bar-row` grid gives the middle column `1fr`, so there's space reserved — it just renders empty. The fix is to make these elements block-level (`display: block` on `.bar-fill`, `display: block`/`inline-block` on `.bar-track`, or switch the spans to `<div>`s). This is the single most visible defect and it hits both the detail and compare views.

### Tab widget declares a contract it doesn't fulfill

`App.tsx` renders `<nav role="tablist">` with buttons carrying `role="tab"` and `aria-selected`. There is no `role="tabpanel"` on the `<main>` content, no `id`/`aria-controls` linking tab to panel, and no `onKeyDown` handling for arrow keys. Screen readers will announce "tab, 1 of 5" and users will expect left/right arrows to move between tabs, but arrows do nothing and the selected content isn't programmatically associated with its tab. Either complete the APG tabs pattern (add `tabpanel`, `aria-controls`, roving tabindex + arrow keys) or drop the ARIA roles and present them as plain buttons. The current half-implementation is worse than either for assistive-tech users.

### Compare view accepts self-comparison

`CompareView` seeds A=USA, B=CHN, but both dropdowns list the full country set with no exclusion. Selecting the same country in both yields a bilateral score comparing a country to itself, displayed under the label "2国間地政学リスクスコア (対称)". Because `bilateralRisk` averages the two countries' `external`/`conflict`, A===B just returns that country's own external/conflict average times the relation factor — a value with no bilateral meaning, presented as if it were valid. Disable the already-selected country in the opposite dropdown, or short-circuit the display when `idA === idB`.

### Map tooltip has no viewport clamping

The tooltip is `position: fixed` and positioned at `left: tip.x + 14, top: tip.y + 14` from the raw mouse `clientX/clientY`. With `max-width: 240px` and no right/bottom clamp, hovering a country near the right or bottom edge pushes the tooltip partly offscreen. Clamp the computed left/top against `window.innerWidth`/`innerHeight` minus the tooltip box, or flip the offset side near edges.

### Array-index assumptions

`MapView` reads `scored[0]`, `scored[scored.length - 1]`, and divides by `scored.length` for the average; `CompareView` seeds state from `countries[1]` and later does `countries.find(...)!` with non-null assertions; `CountryDetailView` falls back to `countries[0]`. All are safe against the current 40-row static dataset but will throw or produce `NaN`/`undefined` if the dataset is ever emptied or trimmed to one row. Cheap guards (empty-state render, or `?? countries[0]`) would make these views robust to data changes.

### Ranking search mixes matching semantics

The filter is `c.name.toLowerCase().includes(q) || c.nameJa.includes(query.trim())`, where `q` is the lowercased trimmed query. The two branches apply two different normalizations of the same input: Latin names case-insensitively, `nameJa` against the raw trimmed string. Harmless for Japanese input, but the asymmetry is a latent bug the moment either name field gains mixed case. Normalize once and apply consistently.

### Test coverage gaps

The domain layer is well covered. Nothing tests the presentation bugs above: there is no test asserting the bars actually have width (the e2e suite screenshots the detail view but never asserts `.bar-fill` has a non-zero rendered width), no test for keyboard tab navigation, and no test for the self-comparison state. The Playwright suite depends on a remote TopoJSON fetch (`cdn.jsdelivr.net`) with a 15s timeout, so the map test is network-dependent and will flake offline. Not tested: bar rendering width, tab keyboard/ARIA panel wiring, compare self-selection, tooltip edge positioning.
